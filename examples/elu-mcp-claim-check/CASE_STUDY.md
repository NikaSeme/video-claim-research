# Case study

## Question

Can product analytics, MCP, and a coding agent make an app fully self-improve like a human?

## Finding

The integration is plausible. ELU publicly describes session analysis, recommendations, pull-request automation, and MCP access. MCP can connect an AI application to outside data and tools. Neither point proves dependable autonomous product judgment or safe unattended deployment.

## Method

1. Preserve the source link and inspect lawfully obtained evidence privately.
2. Separate the literal autonomy claim from the narrower integration claim.
3. Check ELU's public product, privacy, and terms pages.
4. Check primary MCP documentation and independent security guidance.
5. Build the strongest supporting and opposing cases.
6. Assess evidence quality, independence, claim likelihood, and confidence. Do not rate the person.
7. Generate a report with original diagrams, inspect all pages, and run the publication checks.

## Constraints

- No ELU account or API key was available, so the product integration was not tested.
- The reel did not establish whether its analytics view used real, demo, or synthetic data.
- Private comments, messages, and gated material were not accessed.
- The report evaluates the public claim, not the security of a particular deployment.

## Result

Publication revision: 10 September 2026. The underlying evidence assessment is dated 9 July 2026 and has not been refreshed into a new product evaluation. Eight relevant sources remain; personal-profile research was removed.

The best description is “AI-assisted product analysis and code handoff.” Calling the app fully self-improving makes the system sound more autonomous and reliable than the available evidence supports.
